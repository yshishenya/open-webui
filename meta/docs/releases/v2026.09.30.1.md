# v2026.09.30.1 — восстановление Яндекс Метрики

Статус: подготовка выкладки; не считать полной настройкой лендинга и кабинета.

## Что изменилось

- Подготовлена локальная сборка frontend с публичным ID счётчика 111392024;
  образ ещё не собран и не опубликован.
- Docker CI передаёт публичные measurement IDs из repository variables.
- SPA отправляет явные просмотры без автоматического первого дубля и hash-дублей.
- Рекламные метки переживают редирект до согласия в памяти; persistence и отправка
  происходят только после согласия. Секретные query, fragment и title не включаются
  в ручные просмотры; реферер очищается от произвольных query/fragment.
- Вебвизор и автоматическое отслеживание внешних ссылок продукта отключены,
  чтобы не записывать личные данные из интерфейса.

## Validation evidence

- 8/8 focused tests для analytics/consent через Docker Compose; scoped ESLint passed.
- Регрессионный тест original init без defer упал до исправления.
- Production browser baseline: даже при consent granted нет тега и запросов Метрики.
- Tilda browser baseline: нет тега/запросов Метрики; отдельно найдена syntax error Chatra.
- Full typecheck failed: 8363 errors / 226 warnings вне изменённых analytics файлов.
- Две серверные frontend build попытки завершились OOM (exit 134/137), rollout
  не выполнен. Пользователь требует дальнейшую сборку исключительно на Mac.
- Temporary swap удалён; production работает на прежнем образе, healthy, /health=true.
- Локальные команды: `meta/docs/releases/metrica-local-build.md`; синтаксис проверен,
  выполнение на Mac pending. Image publication, rollout и live verification pending.

## Compatibility / migration impact

Изменяется только frontend над immutable production base. Backend, зависимости
и схема БД остаются теми же. Обычные события, цели и ecommerce продолжают
работать после согласия. Вебвизор продукта больше не записывает сессии.

## Known limitations

- Tilda analytics/Chatra и настройки счётчика требуют доступа к соответствующим кабинетам.
- Repository variables и GitHub Release требуют GitHub API/owner доступа;
  SSH deploy key позволяет публиковать ветку и Git tag, но не управлять этими объектами.
- Frontend revenue зависит от consent, blockers и возврата пользователя после оплаты.
- Проверка network delivery не равна подтверждению появления визита в отчётах:
  provider filters и ограничения доменов должны быть проверены в кабинете.
