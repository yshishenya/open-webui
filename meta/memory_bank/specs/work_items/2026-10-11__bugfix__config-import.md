Причина: reader.onload подменяет исходное событие; value очищается у FileReader, выбранный файл остаётся в input. Неверный JSON и ошибка чтения остаются без обработки; отмена выбора вызывает readAsText(undefined). API также скрывает отказ без detail.

Минимальное решение: native File.text(), один обработчик с try/catch, очистка настоящего input и проверка корневого JSON-объекта; существующий requestJSON для тайм-аута и явных ошибок API. Сохраняются URL, метод POST, body {config}, авторизация и ответ конфигурации. Новые зависимости, миграции и подсистемы не нужны.
