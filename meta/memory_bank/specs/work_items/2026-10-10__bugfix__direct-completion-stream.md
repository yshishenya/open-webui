## Goal
Продолжение G14/13.11. Настоящий browser → direct provider → socket → backend путь сохраняет целые строки SSE независимо от границ сетевых частей. Один серверный запрос при живой исходной сессии получает один callback; ошибка после начала потока передаётся через исходный socket channel до done. Повторного запроса провайдера нет.

## Acceptance Criteria
- [x] Воспроизведены разрыв строки и второй callback в настоящем обработчике.
- [x] Использован существующий splitStream и native TextDecoderStream: UTF-8, CRLF, последняя строка без перевода, пустой поток.
- [x] При живой исходной сессии до начала ответа ошибка даёт один структурированный callback; после ack ошибка идёт в channel и затем done. Нет печати ключей, кода, запроса или тела ответа.
- [x] Сохраняются исходная сессия и данные запроса; prefix применяется только к копии model. JSON и SSE договоры сохранены, новых повторов нет.
- [x] Полные frozen frontend/types/ESLint без новых диагностик; backend, чужие изменения, production и соседи сохранены.
- [ ] Source/remote совпадают; SDD закрыта по доказательствам. Общие gates качества и выпуск отдельно.

## Root cause and callers
Root chatEventHandler делит каждый сетевой chunk на строки отдельно и пытается вернуть позднюю ошибку через уже использованный callback. Backend generate_direct_chat_completion принимает ack и затем ждёт события channel; done завершает поток. Два playground потребителя того же chatCompletion уже используют TextDecoderStream/splitStream и не участвуют в socket RPC. Backend остаётся прежним; API helper сохраняет договор и выводит безопасный текст сетевой ошибки.

## Upstream impact
Минимальная замена ветви прямого ответа в root layout с импортом существующего splitStream. API-помощник chatCompletion выводит только безопасный текст сетевой ошибки, сохраняя исходный отказ для вызывающего кода. Без нового runtime модуля, зависимостей, API и изменений квоты или денежных расчётов.

## Limits
Контролируемые Response/ReadableStream воспроизводят обработчик и native поток. Они не подтверждают внешний provider, фактический расход, браузер на телефоне или production выпуск. Pyodide — следующий отдельный путь; timeout сетевого запроса в этой партии не добавляется.
