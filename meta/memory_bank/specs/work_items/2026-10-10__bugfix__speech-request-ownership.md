## Context / Goal

Продолжение обязательного пути выпуска A/B. Общий synthesizeOpenAISpeech не передаёт отмену fetch и проглатывает сетевые ошибки. ResponseMessage не отменяет озвучивание при уничтожении, ждёт голоса бесконечным interval, может поставить поздний blob в очередь и потерять следующий фрагмент при раннем окончании первого. AudioQueue не освобождает созданные URL и не обрабатывает отказы play.

## Acceptance Criteria

- [x] Исходные сбои воспроизведены настоящими обработчиками/классом/API; журналы сохранены.
- [x] Общий запрос получает AbortSignal; отмена до вызова не обращается к сети, отмена в fetch/body завершается ошибкой; сетевые/HTTP ошибки не превращаются в успех/null. Нет автоматического повтора платного запроса.
- [x] Максимум60секунд на fetch вместе с чтением тела; таймер и слушатель отмены освобождаются при всех исходах. API возвращает готовый Blob: иначе ограничение не покрывает чтение тела у потребителей.
- [x] Оба потребителя передают отмену и проверяют владельца после await; поздний результат не воспроизводится, принадлежащие ему URL освобождаются.
- [x] ResponseMessage при уничтожении/переключении владельца/прерывании отменяет свой запрос и очередь; уничтожение чужого сообщения не останавливает текущий звук. Пустой native voice list не создаёт interval.
- [x] Окончание первого фрагмента при незавершённом синтезе не теряет следующие фрагменты; отказ синтеза не запускает дальнейшие платные запросы.
- [x] AudioQueue освобождает blob URL при окончании/ошибке/остановке/уничтожении, не трогает обычные URL; поздний отказ play не изменяет нового владельца; слушатели снимаются.
- [x] Полный frontend проходит, новых types/ESLint нет, замороженные исходники и защищённые данные сохранены, SDD закрыта, изменения закоммичены и отправлены.

## Scope / Upstream impact

audio/index.ts: минимальный общий запрос с существующим getErrorMessage, native AbortController, timer и полным чтением тела. Единственные потребители — CallOverlay и ResponseMessage; оба переводятся с Response на Blob. AudioQueue остаётся существующим владельцем очереди/ссылок; новый общий класс не создаётся. CallOverlay при открытии останавливает старую общую очередь. Новые проверки в utils/airis; существующая извлечённая call audio обвязка получает настоящий audioQueue store.

Без новых зависимостей, изменений API сервера/схемы/цен/учёта денег и настоящего запуска камеры/микрофона. Таймаут браузера не гарантирует отмену уже выполняющейся операции/списания на сервере; финансовая приёмка проверяется отдельно по серверным данным.
