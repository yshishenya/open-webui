## Goal / Acceptance Criteria

Владелец без знания внутренних расчётов понимает продукт, воронку и деньги за 30 секунд, находит клиента/проблему за минуту. Пользователь за 15 секунд понимает денежный и бесплатный доступ, за 30 секунд — расход ответа.

- [ ] Отдельный рабочий раздел: обзор продукта, воронка, деньги, клиенты; дополнительные использование, возвращаемость, качество данных и настройки без перегрузки первого экрана.
- [ ] Строгие пути проверяют порядок событий; все первые оплаты включены в общий результат. Зрелость, неизвестные источники, пропущенные события и разные точки отсчёта не смешиваются.
- [ ] Одна денежная методика: подтверждённые зачисления TOPUP, проверенные возвраты, UsageEvent, остатки сейчас отдельно. Валюты не складываются, использование не названо себестоимостью или прибылью.
- [ ] Понятная история без двойного расхода; estimated оплаченный ответ не помечен «Не списано», отмена не помечена обработкой; неполная история явно обозначена.
- [ ] Баланс/операции/настройки оплаты, доступность бесплатного использования выше пополнения, точные суммы и правила автопополнения; старые ссылки и возврат к чату работают.
- [ ] Цены, бесплатный доступ и исторические подписки имеют точные действия и реальные показатели без демонстрационных трендов.
- [ ] Даты UTC, применённые фильтры и путь назад сохранены; устаревшие ответы запросов не меняют текущий экран; ошибки не подменены нулями.
- [ ] Денежные сценарии, разрешения ordinary/admin, браузер 360/390/768/1280, клавиатура, обе темы; автоматические проверки, независимая проверка, PR и выпуск с текущими доказательствами.
- [ ] Испытание с пятью нетехническими участниками отдельно: 4/5 на каждое задание; не выдавать технические проверки за выполненный пользовательский тест.

## Scope / Implementation

Переиспользовать существующие API/компоненты. Расширять отчёты аддитивно, без новых зависимостей, миграций, изменения роли пользователя и механики реальных списаний. Текущий код b889e8bc53455bfbf798e5d44f7fa288f99af108 сверяется с аудитом cd41a2603.

Ответственность: backend отчёты/тесты — audit_analytics; административный биллинг — audit_admin_billing; пользовательский биллинг/стоимость — audit_user_billing; рабочий раздел аналитики, общая навигация, интеграция/документы/приёмка — root. Все работают в общей изолированной копии.

## Upstream impact

Новая оболочка и вычисления в Airis-owned компонентах/утилитах. Старые входы analytics — тонкие подключения, admin layout — узкая навигационная правка. Billing-specific страницы уже принадлежат форку. Без широкого форматирования upstream.

## Verification

Docker Compose-first: backend pytest + black, Ruff; frontend Vitest, check, lint, build; целевые E2E и независимая проверка. Прежние ограничения разрешённого typecheck/Ruff не скрываются; новые ошибки исправляются. Изолированный Compose project, production данные не используются в тестах. Реальные оплаты/возвраты не выполняются агентом.

## Risks / Rollback

Риск: смена семантики даты платежа/конверсии меняет исторические отчётные числа. Методика видна в интерфейсе и тестах. Производственные денежные записи не правятся. Откат — предыдущий проверенный образ приложения; аддитивные API поля совместимы.

## Совместимость библиотек

Проверены lockfile Svelte 5.56.0 / SvelteKit 2.68.0 и официальные документы legacy reactivity/routing. npm latest 04.10: Svelte 5.57.1 / SvelteKit 3.0.0. Здесь не вводится/заменяется зависимость: используются закреплённые версии и legacy-компоненты форка с vite-plugin-svelte 4.0.4. Обновление SvelteKit 3 требует отдельного совместимого обновления Vite/plugin и проверки форка; не смешивать его с денежным интерфейсом.

Изолированные проверки используют проект Compose airis-analytics-ui и временный override /tmp/airis-analytics-compose.yaml. Новая сеть не выделилась из-за исчерпания адресного пула Docker; используется существующая тестовая сеть airis-acceptance_default, данные/тома отдельные, без ключей YooKassa/почты.

Возвращаемость: наблюдение 1790906400 (02.10.2026 02:00 UTC) взято из принятого production rollout отчёта cohorts; не вычисляется по первому событию. Более ранние регистрации не получают искусственных нулей. Источник: существующий локальный документ 2026-10-02**ops**cohort-production-rollout.md.
