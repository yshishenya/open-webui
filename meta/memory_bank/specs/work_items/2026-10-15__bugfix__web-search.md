## Ошибка и решение

[BUG] Поле `queries` в ответе модели могло содержать `null`, число, строку или список с элементами другого типа. Поиск в интернете записывал это значение в кэш и затем падал на `len`/`strip` либо отклонял запрос. Поиск в файлах мог оборваться или передать неверные данные в поиск документов.

Использована существующая схема `SearchForm` в обоих местах разбора ответа: до записи в кэш и до поиска документов. При ошибке действует прежний возврат к исходному вопросу, без повторного вызова модели. Журнал содержит только тип ошибки, без содержимого ответа. Подготовка запросов для поиска в интернете перенесена в один частный асинхронный метод; новых парсеров, классов, настроек и зависимостей нет.

## Область изменений

Изучены все потребители `generate_queries`. Прямой API продолжает возвращать ответ поставщика; у поиска в интернете и файлах отдельные места разбора данных. Вызов поиска в интернете остаётся после проверки прав в `process_chat_payload`. Подготовка изображения имеет другой контракт и не меняется.

Валидные запросы, порядок событий и источников, приоритет коллекций, отмена, обработка `JSONResponse`, запись в кэш до замены пустой строки и прежнее поведение обрезанного JSON сохранены. Сравнение синтаксических деревьев подтверждает: после обратной подстановки извлечённого метода отличаются только две проверки данных и безопасное журналирование ошибок.
