## Context

Основа — `origin/airis_b2c`, полный SHA `a78b95932936c97651baefe9955f7b8dfdb42d86`, отдельная рабочая папка. Прежние незавершённые изменения основной папки не затрагиваются. Исправление проверяется на закреплённой версии aiosmtplib 3.0.2; сведения о рабочих образах и внутренних наблюдениях остаются в локальном аудите.

`send_message()` и `quit()` находятся в одном блоке повторов. Если сообщение принято, а закрытие соединения падает, повтор создаёт второе письмо. Таймаут во время send_message также повторяется без знания приёма. Date/Message-ID отсутствуют. Ошибки логируются с полным текстом исключений и адресом получателя.

## Goal / Acceptance Criteria

- [x] SMTP acceptance + QUIT error возвращает accepted, одна отправка.
- [x] Сетевой сбой до отправки повторяется ограниченно, с прежним backoff.
- [x] Явный временный SMTP-отказ допускает повтор; постоянный отказ не повторяется.
- [x] Таймаут/разрыв во время отправки возвращает unknown без автоматического повтора.
- [x] Date и Message-ID корректны; один Message-ID сохраняется во всех попытках логической отправки.
- [x] Reply-To задаётся optional ENV, проверяется на инъекцию заголовков.
- [x] Соединение закрывается после неудачного AUTH и после ошибки QUIT.
- [x] Логи транспорта не содержат адресов, SMTP-паролей, тел писем и сырых ответов сервера.
- [x] Существующие `send_email()` и методы шаблонов сохраняют bool-контракт; новый результат доступен будущей очереди.

## Scope / Implementation Notes

Переиспользовать общий EmailService и MIME/Jinja. Изолировать классификацию и повторы в `utils/airis/email_delivery.py`, оставить тонкий вызов в `utils/email.py`. Добавить `send_email_result()` с типизированным результатом accepted/failed/unknown, Message-ID и числом попыток. `send_email()` возвращает true только при accepted; false не является доказательством недоставки. Новая очередь должна использовать структурированный результат.

Не устанавливать новую библиотеку SMTP. Закреплённая и установленная версия — 3.0.2; текущая stable PyPI на момент проверки — 5.1.3. Официальные smtp.py/errors.py тега v3.0.2 прочитаны: SMTPResponseException с 4xx/5xx и SMTPRecipientsRefused подтверждают отказ; timeout/disconnect во время send_message — неоднозначный исход. Переход через две основные версии выделить в отдельную совместимую задачу с проверкой TLS/AUTH, MIME и ошибок. Этот фикс не вводит и не заменяет зависимость старой версией.

Существующий send_message не даёт надёжной фазы DATA для произвольного сетевого исключения. Консервативно считать такой исход unknown даже если некоторые сбои фактически происходят раньше DATA. Это предотвращает дубли ценой отдельного разбора неизвестных отправок; уточнение фазы возможно позже при измеренной необходимости.

## Risks / Rollback

Unknown не означает failed; существующие bool-вызовы не различают эти исходы, поэтому лог и будущий журнал должны сохранять различие. Новый результат не гарантирует exactly once через SMTP. Откат — возврат изолированного изменения транспорта и ENV; миграций БД нет. Локальная готовность не доказывает выпуск на сервере или доставку во Входящие.
