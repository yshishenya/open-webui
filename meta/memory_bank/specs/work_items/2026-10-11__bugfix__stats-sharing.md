## Причина

SyncStatsModal устанавливает собственный глобальный обработчик verify:chat, который обходит origin-проверку родителя. Статистика и ошибки отправляются в opener с targetOrigin '*', до выбора Sync. Cancel меняет только состояние экрана: поздняя страница продолжает отправляться и отмечается успешно завершённой. При скачивании ошибки NDJSON проглатываются, поэтому повреждённый ответ может превращаться в неполный JSON-файл с видом успешной выгрузки.

## Критерии

- [x] До нажатия Sync статистика не запрашивается и не отправляется в другое окно.
- [x] Принимается только разрешённый origin (прежние same-origin и localhost:9999) и точный opener; непустой строковый chatId проверяется до запроса.
- [x] Данные, ошибки и requestId отправляются только origin и окну, закреплённым при согласии. После отмены/закрытия/уничтожения поздние результаты не отправляются и не показывают успех.
- [x] Обычные пагинация, оба формата verify:chat и загрузка корректного UTF-8 NDJSON работают. HTTP-ошибка, пустой body и повреждённая строка не создают файл.
- [x] Целевые воспроизведения падают на исходном коде и проходят после исправления. Полный frontend проходит; новых type/lint замечаний нет, scoped lint/format проходят.

## Реализация

Один счётчик операции и существующие обработчики компонента. Никаких новых библиотек, очередей или абстрактного менеджера. Parent передаёт origin после прежней проверки и проверки точного opener. При ?sync=true разрешённый referrer определяет origin; отсутствие/неразрешённый referrer не разрешает обмен данными. Только сигнал loaded без данных допускает '*', чтобы сохранить начальную связь. Локальная JSON-выгрузка не даёт согласия на обмен с внешним окном. Error helper существующий getErrorMessage. Типы — unknown для внешних сообщений, Readable<I18n> для контекста; прежние поля sync-запроса.

Upstream impact: SyncStatsModal.svelte и +layout.svelte; маленький hook origin в родителе, исправления внутри существующего компонента. API/backend/schema не меняются. Svelte 5.56.0 / TypeScript 5.9.3 / Vitest 1.6.1 из принятого lock, новых библиотечных API нет.
