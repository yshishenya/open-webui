## Решение и границы

Редакторы имеют busy-флаг и ожидают явный результат. Пользователь может продолжить менять черновик во время ожидания; успешный ответ очищает его только при совпадении с отправленным снимком. Повторные Save/Send/Copy и Cancel во время ожидания защищены.

Обычное сохранение запроса/ответа и копии использует существующий updateChatById с одним сообщением в history.messages. Backend уже объединяет входящую карту с сохранённой, восстанавливает childrenIds по parentId и не выводит удаление из отсутствующих id. API подтверждает сохранённый target; локальное изменение производится после подтверждения и только в исходном чате/истории. Копия переиспользует id при отказе в пределах смонтированной истории. Другие сообщения и их текущие обновления не заменяются снимком всего чата.

Отправка изменённого запроса остаётся путём sendMessage: ожидание callback подтверждает окончание вызова, не успешный ответ модели. Известные ранние void-выходы sendMessage и неоднозначные исходы генерации не переименовываются в успех операции. Полная приёмка генерации/долговечного успеха остаётся в G01/G05. Между устройствами нет новой системы версий; изменение одного и того же сообщения по прежнему серверному контракту требует отдельной проверки.

Upstream impact: UserMessage.svelte/ResponseMessage.svelte — тонкие изменения ожидания и busy; Messages.svelte — существующая точка редактирования и sparse-запись. API, backend, политика бесплатных запросов/денег и разрешения не меняются. Переиспользуются ChatHistoryMessage/ChatMessageEdit, native structuredClone и уже установленный equal. Новых Any/подавлений нет. Официальные версии и документы Svelte/TypeScript сохранены в доказательствах предыдущего этапа; зависимости не меняются.
