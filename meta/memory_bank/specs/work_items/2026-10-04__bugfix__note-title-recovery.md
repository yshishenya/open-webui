## Дефект и первопричина

В общей работе G14 / разделе «Заметки» подтверждён отдельный дефект. NoteEditor перед запросом стирает заголовок; generateOpenAIChatCompletion повторно выбрасывает ошибку fetch или ответ 403, а обработчик не имеет внешнего catch/finally. Заголовок остаётся пустым, titleGenerating — true, редактирование заблокировано. Исходная проверка через настоящий API-помощник: 3 падения / 5 успешных случаев. Это отдельная поправка поведения; полная типизация заметок остаётся открытой.

## Измеримые критерии

- [x] Отказ fetch, 403 и неправильный JSON не выбрасывают необработанную ошибку; прежний заголовок и весь текст сохранены, titleGenerating=false, показана существующая переведённая ошибка.
- [x] Во время ожидания заголовок остаётся видимым; правильный ответ применяет обрезанный заголовок и вызывает одно сохранение.
- [x] Пустой или непригодный ответ не стирает заголовок; повторная попытка работает.
- [x] После перехода в другую заметку поздний ответ не меняет её и не сохраняет чужой заголовок; повторный запуск занятой операции не делает второй запрос.
- [ ] Полный Docker frontend, сравнение общих типов/ESLint, документы/SDD и exact CI подтверждены; 0 новых диагностик.
- [ ] Исходники объединены в airis_b2c. Выпуск и браузерная приёмка общего кандидата записываются отдельно.

## Подход и границы

Сохранить заголовок до получения результата, поставить обработку ошибок и снятие индикатора в общую функцию generateTitleHandler. Использовать существующие API и перевод Failed to generate title. Не добавлять помощники, зависимости или повторные платные запросы. Проверить все вызовы API: основной чат уже обрабатывает отказ, здесь изменяется только обработчик заметки. Совместное редактирование, содержимое, права и NoteForm не меняются.

## Upstream impact

Один upstream-owned NoteEditor.svelte, обработчик заголовка и устранение существующих нарушений проверки в этом файле. Добавляется одна проверка, исполняющая извлечённый из текущего файла обработчик и настоящий generateOpenAIChatCompletion с управляемым fetch. Это проверка логики, браузерную приёмку выпуска она не заменяет.

## Проверки и откат

Docker Compose-first: целевая проверка до/после, все frontend-тесты, npm run check и npm run lint:frontend с явным общим остатком. ## Уточнение после полной проверки файла

Для приёмки изменённого файла устранены 12 старых нарушений ESLint: удалены неиспользуемые импорт, начальное состояние и функции без действующих вызовов; setTimeout типизирован через ReturnType. Фактические кнопки отмены/повтора используют editor.chain(), а вставка файлов — RichTextInput. Они сохранены.

Из async executor загрузки изображения вынесен await преобразования HEIC. Ошибка преобразования теперь отклоняет именно Promise вызывающего обработчика; добавлен reader.onerror, чтобы ошибка чтения не оставляла ожидание бесконечным. Успешные PNG/HEIC, отказ преобразования/чтения/сжатия проверены отдельно. Входной file и результат изображения описаны конкретными типами. Новые платные запросы не добавляются. Браузерная проверка общего кандидата остаётся обязательной.
