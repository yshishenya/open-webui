## Context

Продолжение критического пути выпуска A/B. История и поиск входят в обязательный пользовательский путь. SearchModal не проверяет владельца запоздавших ответов предпросмотра и генерации названия. confirmRename использует изменяемый editingChatId после await и может обновить другую строку. Девять отказов воспроизведены настоящим скриптом компонента при управляемом порядке ответов; положительная генерация уже проходит.

## Goal / Acceptance Criteria

- [x] Поздний ответ не заменяет текущий предпросмотр; выбор действия, закрытие, новый поиск и уничтожение отменяют применение старого результата/ошибки.
- [x] Чат без history не показывает историю предыдущего чата.
- [x] Генерация названия сохраняет ответ только в своё действующее редактирование; отмена до получения чата не вызывает provider.
- [x] Сохранение захватывает id/title до запроса; ответ не стирает новую правку.
- [x] Связанные контракты Sidebar/Search/папок имеют конкретные типы; полные проверки не добавляют диагностик и все тесты проходят.
- [x] Backend/production/чужие данные сохранены, документация и проверенный source SHA отправлены. Общий план/цель не закрываются этой партией.

## Scope / Upstream impact

Минимальные изменения в существующих layout/SearchModal.svelte, layout/Sidebar.svelte и контрактах передаваемых обратных вызовов папок. Использовать существующие SavedChat/ChatHistory/Folder/Channel формы и native DOM; без новой зависимости, общей обёртки или ослабления правил. Регрессии в fork-owned utils/airis.

## Verification / Risks

Docker Compose-first: воспроизведение реальным извлечённым скриптом, положительные и отрицательные ответы, полный frontend, полные comparisons types/ESLint, адресный format/diff и хеши. Эти проверки не подтверждают внешнюю доставку/оплату/физический телефон или новый выпуск. Главный риск — перепутать пользователя/выбор/редактирование при асинхронном ответе; каждое изменение владельца должно инвалидировать ответ.
