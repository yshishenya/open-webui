## Причина и область

UserMessage клонирует сохранённое сообщение, но editedFiles затем получает тот же массив message.files. Оба удаления делают splice; «Отмена» не восстанавливает изменённый массив отображаемого сообщения. Одна копия массива при начале редактирования исправляет оба пути. Объекты вложений не меняются: сохранение id/url/content_type/всех дополнительных полей обязательно.

Upstream impact: UserMessage.svelte — изоляция массива и существующие типы/DOM; Message.svelte — удалить только неиспользуемый onInsertToNote у UserMessage, если подтверждена неприменимость; остальные ответные ветки сохраняются. Fork-owned chat_history.ts описывает существующие user/meta по текущим потребителям и backend/subagents, переиспользуя типы дочернего результата. Разметка, permission/readOnly/compactPreview, источники файлов, денежные/бесплатные правила и backend не переписываются.

Подтверждение редактирования сейчас не ожидает общий async editMessage в пользовательской и ответных ветках. Его полная обработка отказов сохранения/отсутствующей модели требует отдельной проверки общего контракта; этим этапом не закрывается и не имитируется.

Проверки Docker Compose-first; настоящие сообщения/файлы не удалять. Доказательства: /Users/yshishenya/.codex/private-artifacts/airis-user-message-draft-isolation-20261009. Браузерная приёмка выпущенной версии остаётся отдельным условием.
