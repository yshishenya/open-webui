## Реализация

Использовать существующие `declare_scope`, `preference_for_user`, `EmailQueueConfig`, `observe_scope_page`, `reconcile_email_candidates` и защищённый отчёт. Не создавать новый сервис, опросник или механизм согласия. Инструкция: [email_pilot_runbook.md](../../guides/email_pilot_runbook.md).

## Upstream impact

Исходники приложения не меняются. Добавлены только документы AIRIS. Серверная конфигурация получает два уже существующих в репозитории параметра с пустым значением/false по умолчанию; до отдельного принятого запуска контейнер не пересоздаётся.

Проверить полный состав отрисованного Compose до/после добавления двух параметров, контрольные суммы сохранённой копии и неизменность контейнеров. Прочитать агрегированную пригодность аккаунтов через существующие модели без DML/SMTP и без адресов. Для документации выполнить `python3 meta/tools/check_markdown_links.py` и CI точного SHA. Функциональные проверки принятого runtime повторять только при изменении исходников или новом отклонении.
