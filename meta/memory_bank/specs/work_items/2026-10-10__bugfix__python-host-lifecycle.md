## Goal
Продолжение G14/13.11: серверный запрос execute:python завершается ровно одним ответом за 60 секунд, включая загрузку выбранных файлов. Нулевой, логический и пустой строковый результат сохраняются. Сбой подготовки никогда не запускает код с неполными файлами. Общий процесс корректно уведомляет ожидающих потребителей при остановке.

## Acceptance Criteria
- [x] Настоящий обработчик воспроизводит потерю 0/false/пустой строки и незавершённые ошибки создания/отправки/загрузки.
- [x] Один callback, явная ошибка, очистка таймеров/обработчиков и отмена загрузки при любом завершении; поздние события не меняют результат.
- [x] Время подготовки входит в лимит; до отправки процесс сохраняется. После отправки остановка уведомляет соседние запросы, сброс хранилища затрагивает только исходный процесс.
- [x] API файлов отклоняет сеть/HTTP/чтение вместо успешного null, сохраняет вызовы просмотра DOCX/XLSX/PPTX.
- [x] Полные frontend/types/ESLint на замороженных исходниках без новых диагностик; сервер, чужие изменения и production сохранены.
- [x] Исходники отправлены, SDD и частные документы обновлены по фактическим доказательствам.

## Root cause and callers
Root создаёт процесс и отправляет сообщение вне защиты, слушатели устанавливает после отправки, отсчитывает время после файлов, теряет falsy результаты, при worker error возвращает пустой успех. API файлов проглатывает сетевые ошибки. Потребители общего процесса: root, CodeBlock, PyodideFileNav; CodeEditor имеет отдельный процесс. getFileContentById используется root и FileItemModal (три формата). Установка слушателей и timeout/cleanup в CodeBlock/CodeEditor уже существуют; повторный новый RPC слой не нужен.

## Upstream impact
Локальная замена executePythonAsWorker в root, минимальный общий договор API файлов, уведомление об остановке в fork-owned createPyodideWorker/SandboxHost и исправление ожидания файловой панели. Без новых зависимостей или изменений денежных расчётов/серверного API.

## Dependencies and limits
Repo pin Pyodide 314.0.3; static lock ABI2026_0, Python3.14. Официальные webworker docs и changelog314.0.3 прочитаны; npm latest314.0.7. Обновление версии не входит в исправление: сохраняется принятый runtime и static manifest; обновлять вместе с подготовленной статикой и проверками обоих режимов отдельной задачей. Runtime Python/параллельное исполнение остаётся отдельной проверкой; контролируемые события не доказывают выполнение Pyodide, сохранность файлов в IndexedDB или production-выпуск.
