# Полная воронка Airis

Спецификация: `meta/memory_bank/specs/work_items/2026-10-01__feature__full-funnel-analytics.md`.

## Определения

Первый визит — первое наблюдаемое событие после согласия; это не вся аудитория
сайта. Регистрация — время создания аккаунта на сервере, связанного с ранее
согласившимся посетителем. Первый запрос — принятый запрос; первый ответ —
успешный непустой ответ, наблюдаемый интерфейсом. У этих сигналов нет содержимого
чатов. Подтверждённая оплата — успешный платёж YooKassa с записью зачисления в
ledger. Возврат — отдельно проверенный через API YooKassa возврат, без изменения
баланса этой подсистемой.

Отчёт администратора «Воронка продукта» показывает окно 7/30 дней от первого
визита. Окончательная конверсия использует только посетителей, у которых окно
полностью прошло. Регистрации, активации и оплаты новых когорт видны, но не
делятся на окончательный знаменатель до завершения окна. Исторические покупки
до включения не импортируются автоматически. Первая оплата определяется с
учётом прежних финансовых записей, поэтому старый покупатель не становится новым.

## Идентичность и согласие

До согласия UUID и источники не сохраняются. После согласия браузер получает
случайный UUID, отправляет разрешённые campaign labels, тип устройства и ClientID
Метрики, когда тот доступен. Backend связывает UUID с аккаунтом из авторизации;
передать чужой user_id в форме нельзя. Во внешние системы идёт отдельный
случайный идентификатор, без email/имени/текста/токена.

Первое касание сохраняется; последняя явная кампания обновляется, direct её не
перезаписывает. Разные устройства до входа невозможно надёжно связать. После
выхода идентичность сбрасывается, чтобы другой аккаунт не получил чужую историю.
Отзыв блокирует новые события сразу, отзывает серверное согласие и очищает
клиентские данные; при недоступности сервера интерфейс явно предлагает повтор.
На сервере после отзыва остаются минимальные даты первых действий и связь с
аккаунтом, чтобы новое согласие не воспроизводило регистрацию/активацию;
источники, события и очередь удаляются.
Не включать autocapture, Webvisor, session replay или автоматическую запись форм.

## Конфигурация

- `AIRIS_ANALYTICS_ENABLED_AT`: UTC epoch seconds начала новой аналитики; 0 —
  безопасный выключенный режим серверной финансовой отправки.
- `AIRIS_POSTHOG_HOST`: HTTPS origin существующего PostHog.
- `AIRIS_POSTHOG_KEY`: ключ существующего проекта для приёма событий; не личный
  ключ управления. Хранить только в приватном серверном env.
- `AIRIS_METRICA_COUNTER_ID`: счётчик 111392024 после сверки владельца.
- `AIRIS_METRICA_OAUTH_TOKEN`: серверный OAuth token с необходимым доступом к
  загрузке офлайн-конверсий существующего счётчика; не публиковать.

Без реквизитов назначения локальные факты могут собираться, но внешняя доставка
не считается проверенной. Пустой ключ не равен настроенному PostHog. Frontend ID
Метрики по-прежнему задаётся при сборке, см. `yandex_metrica.md`.

## Доставка и восстановление

События и задания сохраняются в БД с уникальным ключом. Доставка имеет таймаут,
повторы с задержкой, стабильный UUID для PostHog и состояния очереди. Перед
отправкой проверяется актуальное согласие. Обработчик успешного платежа и
периодическая сверка платежей восстанавливают событие при сбое после зачисления.
Покупка не зависит от возврата браузера. Браузерный дубль покупки подавляется
при серверной отправке; неопределённое состояние конфигурации не даёт дубль.

Транспорт at-least-once: если провайдер принял запрос, а ответ потерялся,
повтор неоднозначен. Нельзя обещать exactly-once внешнюю доставку. Failed/unmatched
не скрываются как успех. Возвраты поступают через `refund.succeeded`: убедиться,
что это уведомление включено в кабинете YooKassa. Пропущенный самим провайдером
webhook требует отдельной сверки; обработчик не доказывает подписку в кабинете.

## Метрика и PostHog

Метрика используется для источников/рекламы/целей. Сервер отправляет реальные
офлайн-конверсии, без искусственных просмотров. Окно привязки офлайн-конверсий
ограничено 21 днём от последнего визита; обработка занимает время. Поэтому
30-дневная полная воронка находится в отчёте продукта/PostHog, а не получается
делением месячных оплат на месячные визиты.

## Приёмка

Проверить в изолированной среде: отсутствие запросов до согласия; новый источник
без потери первого; email/OAuth создание; повторный вход; ошибка/пустой ответ;
две вкладки; оплату без возврата; duplicate webhook/reconcile; сбой между статусом
и событием; очередь после рестарта; частичные возвраты; отказ/отзыв во время
ожидания платежа; admin-only отчёт; отсутствие приватных данных во всех payload.

После сборки: backup, миграция, exact SHA, health и browser consent checks. Затем
дождаться обработки и сверить контрольные события в кабинетах. Реальная покупка
и реальный возврат требуют отдельного разрешения и не подменяются фиктивными
production платежами. Окончательные 30-дневные показатели требуют 30 дней данных.
