# Тестовая среда первой задачи, писем и оплаты AIRIS

Среда нужна для проверки реализации до выпуска и пилота. Используются готовый
образ AIRIS, существующие Docker Compose и проверки. Рабочий сервер и его база
не подключаются к стенду. Подготовка среды не означает, что пилот или вся
пользовательская приёмка завершены.

## 1. Выбрать исходники и готовый образ

Работать в отдельной рабочей папке от актуальной `airis_b2c`. Сохранить полный
`git rev-parse HEAD`, хеш `package-lock.json`, выбранный образ и его digest.
Не считать произвольный старый образ соответствующим текущим исходникам.
Изменения runtime после принятой сборки требуют нового проверенного кандидата.

При подготовке 06.10.2026 использован принятый образ
`airis-provider-test-facts:6b06a68b3`. Его серверные исходники имеют SHA
`6b06a68b35f6efa05566b9341ee018ad42387155`; последующие изменения проверки
границ напоминания не меняют приложение. Частные доказательства содержат
сверку файлов образа и рабочего сервера. Для следующей работы заново выбрать
актуальный принятый образ, а не запускать старый выпуск по этой записи.

## 2. Поднять временный PostgreSQL и приложение

Подставить проверенный образ в `ONBOARDING_PATHS_IMAGE`:

```bash
ONBOARDING_PATHS_IMAGE='<проверенный образ>' docker compose \
  -p airis-onboarding-verification \
  -f .codex/docker-compose.onboarding-paths.yaml \
  -f .codex/docker-compose.onboarding-paths-postgres.yaml \
  up -d --wait onboarding-paths
```

Убедиться, что оба контейнера healthy. В базовых файлах нет опубликованных
портов. Приложение получает только тестовые настройки: данные в tmpfs,
модель и автоматические платёжные ответы на localhost, SMTP на localhost.
Обёртка не запускается без `AIRIS_ONBOARDING_PATHS_TEST=1`; браузерный setup
принимает только адрес сервиса `onboarding-paths`.

Если Docker исчерпал диапазоны сетей, использовать отдельный Compose override
с уже существующей сетью, принадлежащей этой проверке. Сначала проверить её
подсеть и отсутствие другого сервиса с тем же DNS-именем. Подсеть должна
совпадать с тестовым `YOOKASSA_WEBHOOK_ALLOWED_IP_RANGES`. Не удалять чужие
сети, не публиковать порт PostgreSQL и не отключать проверки webhook.

## 3. Выполнить полные браузерные проверки

```bash
ONBOARDING_PATHS_IMAGE='<проверенный образ>' docker compose \
  -p airis-onboarding-verification \
  -f .codex/docker-compose.onboarding-paths.yaml \
  -f .codex/docker-compose.onboarding-paths-postgres.yaml \
  run --rm --no-deps e2e \
  'npm ci --legacy-peer-deps && npx playwright test --config=e2e/onboarding-paths.config.ts'
```

Повторить те же `-f` для своего сетевого override, если он использован при
запуске. Версии Playwright в lockfile и браузерном образе должны совпадать.
Результат — 24 случая в двух браузерах, без ошибок страниц и пропусков.
Сохранить JUnit, журнал и трассы отказов из `artifacts/onboarding-paths`.
Выходные файлы можно перенаправить в отдельную частную папку конфигурацией
Playwright и `PLAYWRIGHT_JUNIT_OUTPUT_FILE`. Значение этой переменной из Compose
имеет приоритет над именем файла в конфигурации. При приёмке среды итоговый XML
из стандартной папки скопирован без изменения байтов в частные доказательства.

Эти случаи проверяют локальные ответы провайдера. Они не являются настоящей
оплатой ЮKassa. SMTP-приёмник проверяет протокол и содержимое, но не доставку
во внешние «Входящие». Ширина 390 px не является физическим телефоном.

## 4. Проверить способы регистрации и часы

Использовать уже существующие backend-проверки:

- `test_onboarding_lifecycle.py`: email signup/verify, отдельное согласие,
  два клиента, повторы, временная задача, точные сроки и отписка перед DATA.
- `test_onboarding_first_emails.py`: VKID не доверяет email из браузера;
  Yandex создаёт связь по данным провайдера, проверяет совпадение адреса,
  повторный вход и отключённую регистрацию.
- `test_product_email_preferences.py`, `test_email_delivery_queue.py` и
  `test_task_success.py`: согласия, два обработчика и однократная запись успеха.

Docker Compose-first команда для выбранного набора:

```bash
docker compose -f docker-compose.yaml -f docker-compose.dev.yaml \
  run --rm airis bash -lc 'PYTHONPATH=. pytest -q \
    open_webui/test/util/test_onboarding_lifecycle.py \
    open_webui/test/util/test_onboarding_first_emails.py \
    open_webui/test/util/test_product_email_preferences.py \
    open_webui/test/util/test_email_delivery_queue.py \
    open_webui/test/util/test_task_success.py'
```

Для PostgreSQL одновременно задать три **тестовые** границы базы:
`EMAIL_DELIVERY_TEST_DATABASE_URL`, `EMAIL_PREFERENCES_TEST_DATABASE_URL` и
`TASK_SUCCESS_TEST_DATABASE_URL`. Их базы должны быть отдельными и временными:
фикстуры создают и удаляют таблицы. Не подставлять production URL.
Если задан только первый параметр, остальные проверки используют SQLite:
такой прогон нельзя объявлять полным PostgreSQL.

Принятый набор: PostgreSQL 140/140; SQLite 137 и три PostgreSQL-only случая,
каждый отдельно прошёл на PostgreSQL. В дальнейшем фиксировать фактические
числа текущего набора. Управляемые ответы VKID/Yandex доказывают границы
приложения; настоящий вход через провайдера проверяется отдельно в 07.01.

## 5. Отдельно использовать настоящий тестовый магазин ЮKassa

Ключ тестового магазина хранить в файле вне Git с правами 0600. Не копировать
его в рабочую конфигурацию, команды, журналы или публичные документы.
Перед checkout проверить **этим ключом** `GET /v3/me`: HTTP 200 и `test=true`.
Обычный автоматический стенд выше использует локальный сервис имитации;
он не заменяет эту проверку.

06.10.2026 режим магазина заново подтверждён через GET: `test=true`,
`fiscalization_enabled=true`, новых платежей/возвратов/чеков 0. Предыдущая
отдельная проверка проходила настоящую страницу ЮKassa с test.wallet,
возвратом в AIRIS, точным зачислением, историей и одним перехваченным письмом.
Касса в тестовом режиме имитируется: настоящий фискальный документ и письмо
покупателю этим не доказываются.

## 6. Завершить прогон и сохранить доказательства

```bash
ONBOARDING_PATHS_IMAGE='<проверенный образ>' docker compose \
  -p airis-onboarding-verification \
  -f .codex/docker-compose.onboarding-paths.yaml \
  -f .codex/docker-compose.onboarding-paths-postgres.yaml \
  stop onboarding-paths onboarding-postgres
```

Останавливать только своё Compose-проектное окружение. Сохранить source SHA,
хеши проверок, образ, конфигурацию стенда, JUnit, журналы, время проверки
магазина и ограничения каждого доказательства. Остановка не удаляет общие
сети или том с зависимостями. Production при этой работе не перезапускается.

Следующий этап — [добровольный пилот](email_pilot_runbook.md). Подготовка этой
среды закрывает только 00.08; внешняя доставка, настоящие входы, телефон,
полезность, реальные деньги и календарные окна сохраняют отдельные критерии.
